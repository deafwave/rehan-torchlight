# Stat coverage audit — what the model does not (fully) handle

Comprehensive across **every affix source in the game**, not just the two reference builds.
Generated by walking all `.claude/skills/tli-build/cache/SS12.5-*-en.json` bundles (gear/craft/
blend/corrosion, divinity slates, ethereal prisms, tower sequences, pactspirits, legendaries/
uniques, hero memories/revival, hero traits, kismets, miscellaneous), instantiating each affix
template with a concrete number, applying the same normalization the parser does
(`"N %"`→`"N%"`, `(a/b/c/d/e)` tier arrays, `N:` prefixes), and running every line through the
live `classify()` in `buildParser.ts`. A line is a "gap" iff `classify()` returns `null` **and**
the wording is DPS-relevant for a melee cold/fire/erosion + Blast-Nova-bomb hero.

> Reproduce: the audit script lives in the skill flow (walk bundles → `norm()` → `classify()`).
> Off-build families (Spell, Sentry, Terra, Spirit Magus, Trauma/Wilt/Ignite ailments, Barrage,
> Channeled, Spacetime/Purgatory/gunner traits, Drop-Quantity/Reward economy) are filtered out.

**Status legend**

| tag | meaning | cost to close |
|---|---|---|
| **PARSER** | model bucket already exists — only a `PATTERNS` regex is missing | one line + a `classify` test |
| **MODEL** | no bucket anywhere — needs a `mechanics.md` row + `damageModel.ts` change + failing test | small→large |
| **UPTIME** | folded into a calibration constant (`hits_per_bomb`) or full-uptime assumption, by design | leave unless an A/B drifts |
| **OFF-BUILD** | correct no-op for this hero (other archetype / pure defense) | none |

Source tags in brackets show where each line appears: `gear` `slate` `prism` `sequence` `pact`
`unique` `memory` `trait` `kismet`. Multi-source lines (e.g. `[gear,slate,pact,unique,memory]`)
are the highest-value gaps — they show up everywhere this hero shops.

## Bing export parse status (data/bing1/real_buld_3.json)

Coverage **67% → 77%** over this session (deterioration/bomb/demolisher/projectile/weapon
routing). The remaining ~47 unmatched fall into three buckets, none a simple parser gap:

- **Trait tier-arrays** (`Projectile Quantity (+2/+2/+3/+3/+4)`, `(+10/…/+26)% additional Bomb
  Damage`, Frenzy Hound, Blast Barrage — and Rehan's Rage traits) — **intentionally not
  parser-resolved.** The export keys traits by unlock slot (`level1/45/60/75`) but encodes **no
  active rank**, and the 5-value array can't be safely indexed. Per `mechanics.md#real-build`'s
  **sheet-first** rule, traits are read from the character sheet into the hand-encoded snapshot
  (e.g. Projectile Quantity is `proj_added` calibrated to the sheet's 6, not the trait's `+4`).
  Closing this would need a confirmed rank-selection rule or continued sheet-reads — **not** a
  tier-array parser, which would fabricate numbers that conflict with the calibrated snapshot.
- **Ruinous Star / Obliterate base** (`… True Damage once every 0.33s … 40% increment, up to 6`)
  — structurally parseable, but the base tick %/chance is calibration (chance sums to 148 raw vs
  the sheet-calibrated 98). Kept **inert** on parse; the base stays authoritative in the hand snapshot.
- **UPTIME geometry & stack engines** — Projectile Speed/Size, bomb-count riders, Repentance /
  Feline Stimulant stacks: folded into `hits_per_bomb` or need in-game measurement.

## 4. Correctly OFF-BUILD (present in the pool, no action)

Filtered but noted so the omission is intentional: Spell/Cast (`Spell Damage`, `Spell Crit`,

## How to close a gap (invariants — do not skip)

1. **PARSER wins** (§1): add the `PATTERNS` row routing to the existing bucket + a `classify`
   test. The mechanic is already cited, so no new `mechanics.md` row — but hand-encoded
   snapshots (Bing) stay authoritative regardless.
2. **MODEL gaps** (§2–3): `mechanics.md` row with a confidence flag **first**, then a failing
   test (`damageModel.test.ts` primitive or `bing1/blast-nova.test.ts` build step), then the
   bucket. Invariants #1 and #4.
3. **UPTIME** items are deliberate folds, not bugs — split one out only when a measured A/B shows
   the constant drifts with that stat.
