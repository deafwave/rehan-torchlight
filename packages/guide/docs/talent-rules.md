Moves (all free): point +1 / -1, shift one point (when the budget is full), core add / core swap inside a (tree, set), add a talent tree, raise a tree to a core's need + the core, tree swap (drop tree T with its cores, fill tree U in node order with T's points; the search re-solves points). Core and tree-swap moves are `enabler`: their value may only show after a re-solve.

Legality of a move: only the trees a move touches are checked, and a move is allowed when those trees gain no rule break. Breaks the loadout already had are grandfathered, so an unexplained tree never blocks moves elsewhere. Unknown or foreign node ids are violations, never exceptions.

**Shift selection** (`maxShifts`, default 60; "Move a point" candidates, only when the budget is full): sources = held nodes whose removal breaks nothing, deepest row first (then id); targets for a source = nodes that accept the point and break nothing after the shift, same tree first, then other held trees (node id order). Pairs are taken in anti-diagonal order (class same-tree before cross-tree, then source rank + target rank, source rank, target rank), so the best sources and targets both appear; the first `maxShifts` are kept and the rest named in `notSearched`. Deterministic: no randomness, ties by id.
